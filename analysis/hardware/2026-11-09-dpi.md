# Hardware test: DPI stage and top buttons

Date: November 9, 2026. Device: Razer Naga V2 HyperSpeed, RZ01-0360, USB receiver `1532:00B4`, 2.4 GHz connection.

## Result

The active third stage was temporarily changed from 1600/1600 DPI to 1700/1700 DPI using the app's normal **Apply** action. The new stage table and active DPI were read back. With Naga closed, the user pressed the physical DPI up and down buttons in sequence; separate read-only diagnostics were performed after each step. The app's **Restore Settings Before Last Change** action then restored the pre-test settings.

| Step | Stage table | Active stage | Active X/Y DPI |
|---|---|---|---|
| Before test | 400 / 800 / 1600 / 3200 / 6400 | 3 | 1600 / 1600 |
| Apply and independent read | 400 / 800 / 1700 / 3200 / 6400 | 3 | 1700 / 1700 |
| Physical DPI+ with Naga closed | Same test table | 4 | 3200 / 3200 |
| Physical DPI− with Naga closed | Same test table | 3 | 1700 / 1700 |
| Restore from backup and independent read | 400 / 800 / 1600 / 3200 / 6400 | 3 | 1600 / 1600 |

## Verification

- The independent pre-test hardware snapshot exactly matched the hardware snapshot in the saved Mac profile.
- The pre-operation backup contained both the original raw hardware snapshot and the full Mac profile; both were compared with separate test copies.
- After writing 1700 DPI, only the low bytes of the third stage's X/Y values changed in the raw table: zero-based offsets 19 and 21 changed from `0x40` to `0xA4`. Other raw stage fields were unchanged.
- All 16 button functions were unchanged, including side buttons, wheel tilts and top DPI buttons. The top buttons were already assigned to stage up/down.
- An independent read after closing Naga exactly matched the 1700 DPI snapshot saved by the app after writing.
- The user reported pressing each physical button once. Independent reads showed stage 4/3200 DPI after DPI+ and stage 3/1700 DPI after DPI−. The complete raw snapshot after DPI− exactly matched the snapshot taken after writing 1700 DPI.
- The independent hardware snapshot after restore exactly matched the initial snapshot: 16 raw functions, raw stage table, active DPI, device identity and mode.
- The Mac profile also exactly matched the initial copy, including assignments, local routes and save date.
- No recovery record remained. At the end, Naga was connected in normal mode with the DPI page open, stage 3/1600 DPI active and no unapplied edits.

- `manifest.json`: SHA-256 hashes for the eight evidence files.

The app's pre-operation and first-connection backups were preserved under `~/Library/Application Support/Naga/`. The protocol format was compared with [OpenRazer's DPI stage command](https://github.com/openrazer/openrazer/blob/master/driver/razerchromacommon.c) before writing; code from that source was not run.

## Limits

This test verifies changing one value in a five-stage table, selecting the new value using the physical top buttons, operation with the app closed and a complete restore. It did not verify adding/removing stages, separate X/Y values, persistence after power loss, writes during disconnection or Bluetooth on real hardware. Firmware, device mode and drivers were unchanged. No new app build was made and permissions were not renewed.
